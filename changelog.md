This release brings the following changes:

* New (remremote): the audio streaming engine has been rewritten in Rust and now lives inside NVDA as a small library (`audioEngine/remremote_audio-x64.dll`, plus a 32-bit build for older NVDA versions). The separate `RemSound.Host.exe` helper process and its .NET 10 Desktop Runtime requirement are gone: nothing needs to be installed for audio any more, the runtime prompts and installer are removed, and the stream starts faster. Relayed sessions register with the relay natively (no local UDP shim). The engine speaks exactly the same RemSound wire format as before — key derivation, packet layout, hello/pong punching, Opus settings and inband FEC recovery are all identical — so it interoperates with the Mac app and with the previous version. The Windows Firewall rule for audio now names NVDA itself rather than the removed helper. Remote audio now plays on the output device selected in NVDA's audio settings (and, with the remote synthesizer option, the controlled computer captures that device), falling back to the Windows default with a warning when it is unavailable. Sources in `audio/`, with a test suite and a command-line tool.
* Fix (remremote): the add-on stayed silent and unreachable inside UAC prompts and other secure desktops, even with the configuration copied to the sign-in screen. Joining the local handover bridge failed with an error that was silently discarded; on top of that, the copy of NVDA on the secure desktop tried to start a second control server on a port the user session already held. The handover now works, failures are written to the log instead of being swallowed, and connecting from the sign-in screen (where there is no user session to hand over from) still works as before.
* Fix (remremote): after accepting an untrusted server certificate, reconnecting failed because the encryption key and the "skip verification" flag were mixed up.
* Fix (remremote): a control server whose port is already in use now reports that clearly instead of failing silently, and a machine without a usable IPv6 stack no longer prevents the server from starting at all.
* New (remremote): "Use the speech synthesizer of the remote computer while its audio is streamed" — a checkbox in the add-on options, also on control+shift+NVDA+s. With it on, the controlled computer's speech is no longer sent as text during audio streaming; instead NVDA stays part of the captured audio, so you hear that machine's own voice — its own language and synthesizer. Speech, beeps and sounds return to the control channel the moment streaming stops, including when it stops because something failed. Either computer can flip it with the shortcut; the controlling computer owns and stores the setting, so both ends always show the same state. Flipping it while audio is running rebuilds the stream so it takes effect at once.
* New (remremote): "Keep clipboard in sync" (control+shift+NVDA+k, or the checkbox in the Remote menu) keeps the clipboards of both computers identical while it is on — copy text on either machine and it is available on the other. Either side may toggle it, and the checkbox follows on both. Text only; other clipboard content is left alone.
* New (remremote): remote audio streaming can now also be switched on and off from the Remote menu while connected, not just with the shortcut. The menu checkbox always reflects the real state, including when streaming stops because of an error.
* New (remremote): the audio shortcut now works on the controlled computer too. The audio belongs to that machine, so its user owns the switch: control+shift+NVDA+a there starts or stops sharing it at any time, and the same shortcut on the controlling computer asks for it. Pressed while keys are being forwarded, it simply reaches the controlled computer and toggles it there. Both menu checkboxes follow along.
* New (remremote): when starting a control server without the UPnP option ticked, TeleNVDA now asks whether it should automatically forward the port in your router — and UPnP now opens the port for both TCP (control) and UDP (audio).
* New (remremote): if the .NET 10 Desktop Runtime needed for audio streaming is missing, TeleNVDA offers to install it automatically (via winget, with a browser-download fallback) — once at startup, and again whenever audio streaming is attempted without it.
* New (remremote): remote audio streaming. Control+shift+NVDA+a toggles streaming of the controlled computer's system audio — from either end. NVDA's own audio on the controlled computer is excluded via the Windows process-loopback API (Windows 10 19041+), so its speech isn't heard twice. Audio travels over a separate UDP stream (Opus, AES-256-GCM, RemSound wire format) handled by the bundled RemSound.Host.exe helper, which requires the .NET 10 Desktop Runtime on both machines. The side hosting the connection uses the same port number as the control server — UDP instead of TCP — so only one port number needs forwarding. Direct connections only for now; relayed sessions report an error.
* Handle server connections which break when client sends ALPN information. This should restore connectivity to nvdaremote.com and similar servers.

Important: some anti-virus software may fla parts of this add-on as malicious. Specifically, `url_handler.exe`, which opens `remote://` and `tele://` links. If you don't use this feature, you can safely quarantine or delete the file. Otherwise, you must add it as an exception.
